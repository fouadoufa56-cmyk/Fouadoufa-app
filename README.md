## الجدول

## الجمع بين قسمين أو أكثر

في كل خانة اضغط مربع **«جمع»**، فتظهر قائمة بباقي الأقسام (A و B و C...). اختر قسماً أو أكثر، فيُسجَّل الدرس **تلقائياً** في خانة نفس اليوم والوقت بجدول القسم المختار، بنفس المادة والأستاذ والقاعة والنوع (ويُوسَم بـ «جمع» فلا يظهر تنبيه تعارض الأستاذ).

- خانة القسم المختار تصير **للقراءة فقط** ويظهر فيها «🧷 جمع مع القسم X». أي تعديل تسويه على الخانة الأصلية ينعكس عليها.
- **الجمع يستبدل** ما كان مكتوباً في خانة القسم المختار.
- لو ألغيت «جمع» أو أزلت القسم من القائمة، تُفرَّغ خانته ويرجع يملأها بنفسه.
- لو جمعت مربع «جمع» بلا اختيار قسم، يبقى السلوك القديم (علامة فقط بدون نسخ).
- لو قسمان جمع كل منهما الآخر، يملك القسم الأسبق بالترتيب (A قبل B).


**قاعة واحدة فقط:** لو كتبت قاعة واحدة بالإعدادات، تُملأ تلقائياً في كل خانات الجدول (بدون قوائم قاعة). لو أكثر من قاعة تختار لكل خانة.

رجعنا للطريقة الأولى: الأيام صفوف والفترات أعمدة، وكل خانة فيها قوائم اختيار
(المادة، الأستاذ، القاعة، النوع Cours/Controle/EFM، وجمع). القسم الثاني من
كل زوج (B يتبع A مثلاً) يُملأ تلقائياً من الأول، ويمكن إلغاء الربط لأي خانة
من مربع 🔗. اختيار «-- اختر القاعة --» يعني بلا قاعة.

## تحسين الأداء

1. **ملفات PDF وExcel تُبنى عند الضغط فقط**: كان التطبيق يبني كل الملفات مع كل تعديل (أثقل جزء). الآن تضغط «⚙️ جهّز» فيُبنى الملف مرة واحدة ويظهر زر التحميل. لو عدّلت الجدول بعدها يُلغى الملف الجاهز (لئلا تحمّل نسخة قديمة) وتجهّزه من جديد. (وصار زر PDF يظهر لكل الأقسام، حتى لو أكثر من 4.)
2. **الجدول يتحدّث وحده** (`st.fragment`): تعديل خانة يعيد رسم الجدول فقط وليس الصفحة كلها. الحفظ (على السيرفر والمتصفح) وأزرار التحميل و«آخر حفظ» صارت داخل نفس المنطقة لتتحدّث معها. يتطلب Streamlit 1.37 أو أحدث؛ ولو كانت نسختك أقدم يعمل التطبيق بالطريقة القديمة بدون هذا التسريع.

تغيير الإعدادات أو تاريخ الجدول أو المواد النشطة يعيد تحميل الصفحة كلها كالمعتاد.

## يوم السبت (اختياري)

بالإعدادات (⚙️ إعداد الأقسام...) فيه خيار «➕ تفعيل يوم السبت (Samedi) بالجدول». لما تفعّله:
- يضاف صف Samedi لكل الجداول (فارغ في البداية)، وتقدر تعبّيه متل باقي الأيام.
- يظهر تلقائياً بملفات PDF وExcel المصدَّرة.
- لو ألغيته بعدين، يختفي صف Samedi من الجداول (أي بيانات كانت فيه تُحذف، فانتبه قبل الإلغاء لو عندك بيانات فيه).


## نظام الحسابات المنفصلة — كيف يعمل

- عند فتح التطبيق أول مرة، تظهر شاشة «تسجيل الدخول / إنشاء حساب جديد» ولا يظهر أي جزء من الجدول قبلها.
- كل مستخدم يُنشئ اسم مستخدم وكلمة مرور خاصة به (3-20 حرفاً/رقماً للاسم، 6 أحرف على الأقل لكلمة المرور).
- بيانات كل مستخدم تُحفظ في ملفه الخاص وحده: `user_data/{اسم_المستخدم}.json`. لا أحد غيره يقدر يشوفها من داخل التطبيق.
- زر «🚪 تسجيل الخروج» بالشريط الجانبي يمسح الجلسة الحالية بالكامل.

### ترحيل بياناتك القديمة تلقائياً
عندك بيانات فعلية بملف `saved_data.json` القديم (قبل إضافة الحسابات). **أول حساب تُنشئه بعد هذا التحديث سيأخذ هذه البيانات تلقائياً** — لن تضيع. أي حساب يُنشأ بعد ذلك يبدأ بجدول فارغ (وهذا صحيح ومقصود، حتى لا يشوف حساب جديد جدول حساب آخر).

## الدخول بعد تحديث الصفحة، والحفظ

- **الدخول يبقى بعد تحديث الصفحة أو إغلاق المتصفح** لمدة 30 يوماً (`SESSION_DAYS` في `constants.py`) أو حتى تضغط «تسجيل الخروج». الرمز السري يُحفظ مشفّراً في مكان التخزين (`sessions.json` أو Supabase) وكوكي بمتصفحك. يتطلب Streamlit 1.37 أو أحدث، وإلا يرجع التطبيق لشاشة الدخول عند كل تحديث.
- **الحفظ تلقائي بعد كل تعديل** (لا يوجد زر حفظ ولا مؤقّت)، في سجل حسابك (ملف `user_data/اسمك.json` على جهازك، أو قاعدة Supabase على السيرفر). يحدث الحفظ قبل قسم تحميل PDF، فلا يضيع شيء لو فشل توليد PDF.

## ⚠️ تنبيهات أمنية مهمة قبل النشر

1. **لا تضع `users.json` ولا مجلد `user_data/` على مستودع GitHub عام.** أضفتهما إلى `.gitignore` الجاهز في هذا المشروع، تأكد إنه فعلاً يمنع رفعهما (`git status` يجب ألا يُظهرهما).
2. هذا نظام دخول **بسيط** يناسب فريق صغير موثوق (مدرسة، إدارة واحدة). لا يوجد فيه:
   - استرجاع لكلمة مرور منسية
   - تحقق من البريد الإلكتروني
   - حماية من محاولات الدخول المتكررة (brute-force)

   لو تحتاج تطبيقاً بمستوى أمان أعلى (موقع عام يستخدمه مئات الأشخاص)، هذا يحتاج بنية مختلفة (قاعدة بيانات + خدمة مصادقة جاهزة)، أخبرني لو وصلت لهذه المرحلة.
3. **التخزين على السيرفر**: على سيرفر مثل Streamlit Cloud قرص التخزين **مؤقت** (يُمسح عند إعادة التشغيل أو التحديث). لذلك فعّل Supabase كما في القسم التالي، وإلا ستضيع الحسابات والجداول.

## ثلاثة حسابات ثابتة (بدون قاعدة بيانات)

لو تريد 3 حسابات فقط تبقى للأبد على Streamlit Cloud: نصنع ملف `users.json` بحساباتك ونرفعه إلى GitHub، فيرجع معه كل إعادة تشغيل. وبعد بلوغ 3 حسابات يختفي تبويب «إنشاء حساب جديد» تلقائياً (الرقم في `MAX_ACCOUNTS` بملف `constants.py`).

1. **اجعل المستودع Private**: GitHub ← المستودع ← Settings ← أسفل الصفحة Danger Zone ← Change visibility ← Make private. (ملف الحسابات فيه بصمات كلمات المرور، لا يصح أن يراها أحد.)
2. **أنشئ الملف على جهازك** (يحتاج Python، وهو عندك لأنك تشغّل التطبيق): افتح الطرفية داخل مجلد المشروع وشغّل
```bash
python make_users.py
```
أدخل أسماء المستخدمين الثلاثة وكلمات مرورهم (أحرف كلمة المرور لا تظهر وأنت تكتبها، هذا طبيعي). سيُنشأ `users.json`.
   - *بديل*: شغّل التطبيق محلياً (`streamlit run app.py`) وأنشئ الحسابات الثلاثة من شاشة «إنشاء حساب جديد»، فيُنشأ `users.json` بنفس المجلد.
3. **ارفعه إلى GitHub**: افتح المستودع ← **Add file ← Upload files** ← اسحب `users.json` (سيستبدل القديم) ← **Commit changes**. (أو افتح `users.json` الموجود واضغط القلم ✏️ والصق المحتوى الجديد.)
4. انتظر دقيقة حتى يعيد التطبيق تشغيل نفسه، وجرّب الدخول بالحسابات الثلاثة.

ملاحظات:
- **تغيير كلمة مرور أو حساب لاحقاً**: شغّل `make_users.py` من جديد وارفع الملف مرة ثانية.
- **جداولك** لا ترجع من `users.json` (هو للحسابات فقط). تبقى محفوظة بنسخة المتصفح (انظر القسم أدناه)، أو بـ Supabase لو فعّلته.
- **لا ترفع** `sessions.json` ولا `user_data/` (مستثناة بـ `.gitignore`). `users.json` وحده هو المقصود.
- لو استعملت `git add .` ولم يُضِف `users.json` (لأنه مذكور سابقاً بـ `.gitignore`)، استعمل `git add -f users.json`.
- أنت من يحتاج `users.json` الجديد بعد أي تغيير حسابات؛ الحسابات التي تُنشأ على السيرفر مباشرة تضيع عند إعادة التشغيل.

## لماذا كان الحساب الثاني يختفي؟ وكيف نُحلّ ذلك

على سيرفر مثل Streamlit Cloud، ملفات التطبيق **ترجع لنسخة GitHub عند كل إعادة تشغيل**. لو كان `users.json` مرفوعاً على GitHub وفيه الحساب الأول فقط، يرجع الحساب الأول فقط كل مرة.

1. **لا ترفع `sessions.json` ولا `user_data/`** على GitHub. أما `users.json` فارفعه **فقط لو المستودع Private** (راجع القسم السابق)؛ لو المستودع Public احذفه منه:
```bash
git rm --cached users.json
git commit -m "remove private data"
git push
```
وبما إن بصمات كلمات المرور كانت ظاهرة، **غيّر كلمات المرور** بـ `make_users.py` أو اجعل المستودع Private.

2. **سجل الحسابات بالمتصفح**: كل حساب تدخل به من متصفح معيّن يُحفظ اسمه وبصمة كلمة مروره (مشفّرة، لا كلمة المرور نفسها) في متصفحك. لو انمسح الحساب من السيرفر، ادخل باسمه وكلمة مروره فيُعاد إنشاؤه تلقائياً، وترجع جداولك من نسخة المتصفح.
   - يعمل فقط **على نفس المتصفح والجهاز** اللي أنشأت منه الحساب أو دخلت به.
   - من جهاز آخر لن يجد الحساب إن كان السيرفر قد مسحه. الحل الدائم الوحيد لهذا هو Supabase (القسم التالي).
   - إنشاء حساب جديد صار يدخلك مباشرة بدون خطوة إضافية.

## نسخة احتياطية داخل المتصفح

بجانب التخزين الأساسي (ملفات الجهاز أو Supabase)، يحفظ التطبيق **نسخة كاملة من جدولك في متصفحك** عند كل تعديل، بلا مدة انتهاء.

- **عند فتح حسابك** يقارن التطبيق وقت آخر حفظ بين نسخة السيرفر ونسخة المتصفح ويفتح **الأحدث**. فلو انمسح السيرفر، ترجع جداولك من المتصفح وتظهر رسالة «♻️ استُعيد جدولك من نسخة المتصفح».
- لو تعذّر الحفظ على السيرفر، تعديلاتك تبقى محفوظة بالمتصفح.
- **حدود**: النسخة مربوطة بهذا المتصفح وهذا الجهاز؛ تنمسح لو مسحت بيانات المتصفح أو استعملت التصفح الخفي؛ وSafari قد يمسحها بعد نحو 7 أيام بلا زيارة.
- **الحسابات** (اسم المستخدم وكلمة المرور) لا تُحفظ بالمتصفح، بل بمكان التخزين الأساسي. لو انمسح السيرفر، أنشئ الحساب **بنفس الاسم** وسترجع جداولك من المتصفح.
- أول فتح بعد الدخول يظهر «جاري قراءة نسختك المحفوظة في المتصفح» لحظة، لأن قراءة المتصفح غير فورية. لو علقت، اضغط «متابعة بدون نسخة المتصفح».

## الحفظ الدائم على السيرفر (Supabase، مجاني)

- **على جهازك**: لا تحتاج شيئاً، البيانات تُحفظ بملفات على قرصك (`users.json`، `user_data/`).
- **على سيرفر (Streamlit Cloud مثلاً)**: التطبيق يحفظ بياناتك في قاعدة Supabase تلقائياً بمجرد وضع الأسرار (secrets) — بدون أي تغيير في الكود.

الخطوات:
1. أنشئ حساباً مجانياً في supabase.com ثم **New project**.
2. من **SQL Editor** شغّل:
```sql
create table app_store (
  ns text not null,
  key text not null,
  value jsonb not null,
  primary key (ns, key)
);
alter table app_store enable row level security;
```
(السطر الأخير مهم: يمنع أي أحد من قراءة جدولك بالمفتاح العام.)
3. من **Project Settings ← API** انسخ **Project URL** و**المفتاح السري** (Secret key، أو service_role في الواجهة القديمة). **لا تستعمل المفتاح العام (anon/publishable).**
4. في Streamlit Cloud: **Manage app ← Settings ← Secrets** والصق (راجع `secrets_example/secrets.toml.example`):
```toml
[supabase]
url = "https://xxxx.supabase.co"
key = "المفتاح السري"
```
5. أعد تشغيل التطبيق، ثم أنشئ حسابك. من الآن كل حساب وجدول يُحفظ في Supabase.

ملاحظات:
- المفتاح السري يبقى في Secrets فقط، **لا تضعه في الكود ولا في GitHub**.
- لو تعذّر الوصول للقاعدة، التطبيق **يتوقف مع رسالة** ولا يبدأ بجدول فارغ، حتى لا يستبدل بياناتك الحقيقية.
- مشاريع Supabase المجانية تتوقف تلقائياً بعد نحو أسبوع بلا استخدام (بياناتك محفوظة؛ تفتح لوحة Supabase وتضغط Restore).
- بيانات `users.json` و`user_data/` القديمة على جهازك لا تنتقل تلقائياً للقاعدة. أول حساب تنشئه على السيرفر يأخذ `saved_data.json` لو كان موجوداً بالمستودع.

## كيف تُشغّله

```bash
pip install streamlit pandas fpdf2 arabic-reshaper python-bidi openpyxl
streamlit run app.py
```

لا تنسَ نسخ مجلد `fonts/` (وبداخله `DejaVuSans.ttf` و`DejaVuSans-Bold.ttf`) لنفس مكان `app.py`.

لا حاجة لأي مكتبة إضافية لنظام الحسابات — يعتمد فقط على مكتبات بايثون القياسية.
